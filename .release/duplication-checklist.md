## Robust schema

The owner's policy: every robust estimate goes through ONE schema — the stack's strategy types and Core's width
resolution (`loss_at` / `lo_loss` / `deploy` / `decision_width`), no private width or scale rules. The items are the
"LODR" section of robust-schema-audit.md (2026-11-11). Decisions taken in the owner's absence are recorded here.

- [x] src/strategies/types.jl `_barron_sq_width`: a private width resolver whose no-width branch took the scorer's threshold itself (skipping `decision_width`) → `sq_loss_width(loss_at(lo, BarronShape(0.0), cs, scoring, buf))`. Decision: the frozen width is resolved at ONE reference shape, Barron's α = 0 (Cauchy): its facet-B decision width t/√2 is the Cauchy loss deciding at the scorer's threshold t, the intent of the old rule in Core's currency. `ScaleMultiple`/`LossWidth`: bit-identical; follow-the-scorer: a behaviour change (c² = t²/2, was t²; fail-first test, no paper arm runs this mode — every BarronAdaptive arm carries a `scale_multiple`) (this commit)
- [x] src/strategies/essential.jl `WelschHQEcm`: the hand-written `deploy(WelschShape(), max(scale_s2(cs), eps()); scale_multiple)` → `loss_at(lo, WelschShape(), cs, scoring, buf)`, with `lo_width(::WelschHQEcm) = ScaleMultiple(lo.scale_multiple)`. Bit-identical. Decision: the arm keeps its ONE mode and gets no `LossWidth` or follow-the-scorer mode (no `width` field, no `with_width`): it is self-scaling, re-estimating ŝ² at a fixed multiple, so an absolute width (a multiple of 1 from `loss_width`) or the scorer's would become 1·ŝ_ECM at the first scale step. Its scale interface stays `SelfScaling` (this commit)
- [x] ext/LocalOptimizationDoneRightPoseLibExt.jl `PoseLibLmAdaptLossWidth`: the width built in place (`scale_multiple * sqrt(s2)`, twice) → `loss_width(deploy(TLSShape(), max(s2, eps()); scale_multiple))` (`_adapt_loss_width`), bit-identical. Decision: the within-width truncated moment IS the arm's definition (accv2026 configs/protocol.toml `[arms.tls_adapt]`: the width "re-anchored on the refined partition"; the docstring's "within-width residual scale"; `min_support` in configs/default.toml), so the partition |r| ≤ width and its support floor stay; its scale is Core's estimator `fit_scale(JeffreysPrior(), rss, ν)` = rss/ν. Width bit-identical; the moment alone now floors at eps where it returned 0.0 for an all-zero partition (the width already floored it) (this commit)
No stack change is needed: VisualGeometryToolkitEstimation src/config_toml.jl `lo_from_toml` cites "LocalOptimizationDoneRight's Welsch-HQ-ECM" as its example of a plain `scale_multiple` FIELD; it stays accurate (the field stays).
